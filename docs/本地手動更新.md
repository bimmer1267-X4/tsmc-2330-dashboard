# 本地手動更新（繞開 GitHub Actions）

## 什麼時候需要用這個

`update-dashboard.yml`／`post-close-update.yml` 這兩個 GitHub Actions workflow 都是在
GitHub 的共用 runner 上執行，出站IP是GitHub提供的共用IP池。如果上游資料來源（尤其是
TWSE 台灣證券交易所的 API）當下對這個共用IP池出現連線層級的暫時性問題（例如連線被
重置 `ECONNRESET`，且不是幾秒鐘內就恢復、workflow 內建的重試機制也救不回來），
不論重新觸發 workflow 幾次都會一直失敗——因為問題不在程式碼，而在「從GitHub Actions
這個網路環境連過去」這件事本身。

這種情況下，改成在**你自己的電腦**上執行同一套資料更新流程，用你自己的網路環境（不同
IP）直接連上游 API，跑完後直接 `git push` 到 `main`，完全不經過 GitHub Actions，藉此
繞開共用IP被卡住的問題。

## 事前準備

1. 已經 `git clone` 這個 repo 到本機，且能直接 `git push` 到 `main`（個人 PAT 或 SSH key
   已設定好，不需要開 PR）。
2. **Mac / Linux**：Node.js >= 18（腳本用到內建 `fetch`，不需要 `npm install`，這些
   腳本沒有外部套件依賴）。
3. **Windows**：PowerShell 7+。

## 兩支腳本，對應兩個 workflow

| 本地腳本 | 對應的 workflow | 用途 |
|---|---|---|
| `scripts/local-run-full-update.sh`（Mac/Linux）<br>`scripts/local-run-full-update.ps1`（Windows） | `update-dashboard.yml` | 日K、技術指標、ADR/匯率、盤前預測、籌碼面等大部分欄位 |
| `scripts/local-run-post-close.sh`（Mac/Linux）<br>`scripts/local-run-post-close.ps1`（Windows） | `post-close-update.yml` | 即時報價(`liveQuote`)卡片、預測準確度回填 |

兩支腳本內部呼叫的**是同一套** `scripts/*.mjs`／`scripts/*.ps1`，跟 workflow 裡執行的
完全一樣，只是換了執行環境（你的電腦，而不是 GitHub Actions runner），行為（包含手動
觸發時間鎖定窗判斷、push撞車重試機制）也刻意做成跟對應 workflow 一致。跑完後兩支腳本
都會自動 `git commit` + `git push`，沒有變更則安靜跳過 commit。

## 使用方式

```bash
cd /path/to/tsmc-2330-dashboard

# 完整每日更新（對應 update-dashboard.yml）
bash scripts/local-run-full-update.sh

# 收盤後更新（對應 post-close-update.yml）
bash scripts/local-run-post-close.sh
```

Windows（PowerShell）：

```powershell
cd C:\path\to\tsmc-2330-dashboard
.\scripts\local-run-full-update.ps1
.\scripts\local-run-post-close.ps1
```

## 注意事項

- 這兩支腳本操作上跟對應的 GitHub Actions workflow / `renew-2330` skill 一樣，都是「重跑
  既有流程」，安全、可重複執行，不會有預期外的副作用。
- 執行前建議先 `git pull` 確保本機是最新的 `main`，避免推送時發生非快進(non-fast-forward)
  衝突。
- 如果本機執行還是連不上同一個上游 API（例如你的網路本身也連不到 TWSE），代表問題不是
  IP被擋，而是該來源真的整體異常，這種情況本地跑跟 GitHub Actions 跑結果會一樣，此時
  才需要進一步排查上游服務本身的狀態。
